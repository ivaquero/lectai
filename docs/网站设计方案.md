## 一、先拆模板：我们要继承什么

模板只有 6 个文件、769 行渲染层，但结构上非常干净。逐项判断哪些值得搬过来：

| 模板里的做法                                                   | 是否继承         | 理由                                             |
| :------------------------------------------------------------- | :--------------- | :----------------------------------------------- |
| 浅色投影配色（`#f2f5f9` 底 / 白卡片 / `#2563eb` 主色）         | ✅ 全盘继承       | 已经是你这个项目的风格底色，继续用等于零成本统一 |
| 顶栏「品牌 + 副标题 + 右侧提示」单行结构                       | ✅ 继承并扩展     | 我们多一个 4 页导航和状态徽标                    |
| `stage`（主舞台）+ `side`（348px 侧栏）双栏                    | ✅ 继承           | 链表演示同样需要「左边看动画、右边看代码」       |
| 播放控制条：⏮ ◀ 播放 ▶ ⏭ ↺ + 对数速度滑杆                      | ✅ 直接照搬       | 单步/回退是教学场景的刚需，这套布局已打磨过      |
| 伪代码面板（行号 + 当前行高亮 + 结构性行灰显）                 | ✅ 照搬           | 链表的指针操作比排序更需要「代码 ↔ 图形」对应    |
| 图例条 + 复杂度 chip 条 + 4 格统计 chip                        | ✅ 照搬，语义换掉 | 排序的「比较/交换」换成链表的「已访问/指针移动」 |
| **步骤轨迹架构**（算法生成器 `yield` → 轨迹数组 → 按游标回放） | ✅ **核心继承**   | 见下节，这是整个方案的地基                       |
| p5.js canvas 渲染                                              | ⚠️ 改用 SVG       | 见 §2.1                                          |
| 单页应用（无导航、无路由）                                     | ❌ 扩展为 4 页    | 模板是单一工具，我们是平台                       |
| 全部逻辑塞进 `sketch.js`                                       | ❌ 拆模块         | 现有 `script.js` 已 2597 行，必须拆分            |

### 1.1 为什么「步骤轨迹」是地基

模板 README 里那句话点得很准：

> 动画不是边跑边画，而是先把整个过程展开成一条**步骤轨迹**，再按播放头回放。
> 这样暂停、单步、后退、跳到末尾都只是移动一个下标，不需要任何逆操作。

链表演示比排序更吃这一套：插入结点要「申请—赋值—改指针」，删除要「找前驱—改 next—释放」，
中间任何一步都可能被学生问"为什么这里顺序不能反"。如果边算边画，回退就得写逆操作，
而链表的逆操作（恢复被覆盖的指针）极易写错。轨迹化之后：

```text
算法跑一遍 → yield 出一串「状态快照 + 高亮信息 + 对应代码行 + 中文解说」
            → 播放器只负责 cursor++ / cursor--
            → 渲染层完全不懂算法
```

### 1.2 建议把轨迹生成放到后端（关键决策）

现有后端只返回**最终状态**（`nodes: [...]`），动画帧由前端自己拼。改成返回**整条轨迹**后：

- **算法只有一份**，跑在 Python 里，和教学用的 C 代码逐行对应，不会出现"前端模拟一套、后端算一套"的漂移；
- 前端退化成纯播放器，`sketch` 层不需要懂链表，只画它拿到的快照；
- 轨迹可直接在 `pytest` 里断言（结点数、指针位置、每一步的 next 指向是否合法），可测试性大幅提升。

代价是接口变重（一次操作返回几十到几百个步骤），但单链表操作步数很少（插入 4–6 步、遍历 n 步），
单次响应仍在几十 KB 以内，完全可接受。

## 二、目录结构规划

### 2.1 渲染层：SVG 取代 p5 canvas

| 方案            | 优点                                                                                                                                             | 缺点                                                                                      |
| :-------------- | :----------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------- |
| p5.js canvas    | 与模板同源，`lerp` 补间方便                                                                                                                      | 文字不锐利（需处理 devicePixelRatio）；结点 hover 要手写命中检测；无法用 CSS 过渡与焦点态 |
| **SVG（推荐）** | 结点是 `<rect>+<text>`，任意缩放清晰；箭头用 `<marker>`，结点移动时自动跟随；hover / focus 原生；插入删除用 CSS `transform` + `opacity` 过渡即可 | 需自己写结点坐标计算（本来也要写）                                                        |

**结论：用 SVG。** 模板的视觉语言（配色、卡片、控件、圆角、阴影）100% 保留，只是把"画布"从
`<canvas>` 换成 `<svg>`。如果后续你更希望保留 p5，只需要替换 `render.js` 一个文件，其余不动。

### 3.2 链表语义色（对应模板的 `COLORS`）

| 令牌             | 色值      | 含义                            |
| :--------------- | :-------- | :------------------------------ |
| `--node-idle`    | `#94a3b8` | 未参与本次操作                  |
| `--node-compare` | `#f59e0b` | 正在比较（同模板 cmp 橙）       |
| `--node-visited` | `#22c55e` | 已访问 / 已确定（同 sorted 绿） |
| `--node-new`     | `#38bdf8` | 本次新建的结点（同 aux 蓝）     |
| `--node-remove`  | `#ef4444` | 即将删除（同 swap 红）          |
| `--node-ptr`     | `#8b5cf6` | 特殊指针（prev / q）            |
| `--null`         | `#cbd5e1` | 空指针 `NULL` 端标              |

> 关键原则：**同一语义在全站同一个颜色**。刷题页的"正确"用 `--ok` 绿，链表演示的"已访问"
> 也用同一支绿，学生扫一眼就知道状态含义。

## 四、全局外壳

四个页面共用一个外壳，只有中间内容区不同。顶栏单行三区，窄屏时导航折到第二行：

```text
┌────────────────────────────────────────────────────────────────────────────────┐
│ ▮ 数据结构学习平台 · 单链表可视化      [首页] [单链表] [刷题] [AI答疑]  ● 已连接 │
└────────────────────────────────────────────────────────────────────────────────┘
   ↑ 渐变竖条 10×18                    ↑ tab 风格，当前页 accent-soft 底   ↑ 状态徽标
```

- **左侧**：模板 `.brand .mark` 那个 10×18 渐变竖条原样保留，作为品牌记忆点；
  站名后跟一个小圆点 + **当前页名**，让人不看导航也知道在哪。
- **中间**：4 个导航项复用 `.tab` 的选中样式（`--accent-soft` 底 + `--accent-line` 描边 + 内阴影），
  不使用下划线，保持模板的克制感。
- **右侧**：后端状态徽标（`● 已连接` / `○ 离线模式` / `检测中…`），hover 显示后端地址、题库数、运行时长。
  再加一条当前页的快捷键提示（模板 `.topbar-note` 的位置），例如链表页显示
  `空格 播放 · ←→ 单步 · R 重置 · N 随机`。
- 顶栏高度 56px，`padding: 0 20px`，`border-bottom: 1px solid var(--border)`，白底 —— 与模板一致。

### 5.2 单链表可视化 `list.html`（核心页）

严格复刻模板的双栏舞台结构，只是把"排序柱状图"换成"结点串 + 指针"。

```text
┌────────────────────────────────────────────────────┬───────────────────────┐
│ [插入结点][删除结点][查找][遍历]                    │ 操作与数据             │
│  头插/尾插   按位/按值   按值   全链访问             │ ┌───────────────────┐ │
├────────────────────────────────────────────────────┤ │ 3, 1, 4, 1, 5      │ │
│                                                    │ └───────────────────┘ │
│   head↓        prev↓        p↓                     │ [应用] [随机] [清空]   │
│   ┌─────┐     ┌─────┐     ┌─────┐     ┌─────┐      │                       │
│   │  3  │────▶│  1  │────▶│  4  │────▶│  1  │──▶ ∅ │ 值 [ 7 ]  位序 [ 2 ]  │
│   └─────┘     └─────┘     └─────┘     └─────┘      │ [头插] [尾插]          │
│     a1          a2          a3          a4         │ [按位删] [按值删] [查找]│
│                                                    ├───────────────────────┤
│  ── 画布区高 clamp(300px, 52vh, 620px) ──           │ C 代码                │
├────────────────────────────────────────────────────┤ 1  s = malloc(...)    │
│ ● 未参与  ● 比较  ● 已访问  ● 新建  ● 待删除  ● ∅   │ 2  s->data = x        │
├────────────────────────────────────────────────────┤ 3  s->next = head     │ ← 高亮
│ ( O(1) 头插 ) ( O(n) 按位删除 ) ( O(n) 查找 )        │ 4  head = s           │
├────────────────────────────────────────────────────┤                       │
│ 当前操作 │ p 停在 a2，比较 1 与目标 12 → 不相等，继续  ├───────────────────────┤
├────────────────────────────────────────────────────┤ 要点提示               │
│ ⏮  ◀  [ ▶ 播放 ]  ▶  ⏭  ↺    速度 ──●──── 24 步/秒 │ 头插后 head 必须指向   │
├────────────────────────────────────────────────────┤ 新结点，顺序不能反。    │
│ 结点 5 │ 已访问 2 │ 指针移动 3 │ 进度 4 / 17        │                       │
└────────────────────────────────────────────────────┴───────────────────────┘
```

**左栏（stage）从上到下 7 块**，顺序与模板完全一致，学生的阅读路径不用重新学：

1. **操作 tabs**：4 组（插入 / 删除 / 查找 / 遍历），每个 tab 内部再列具体操作。
   模板的做法是「tab = 算法」，我们这里「tab = 操作类别」，副标题写一句人话
   （如「头插 · O(1)，改两根指针」）。
2. **画布**：横向结点串。每结点画 3 层信息：
   - 矩形框 + 居中数值（等宽字体，大一号）；
   - 框下方灰色小字位序 `a1 / a2 / a3`（逻辑序号，用于对齐"第 i 个结点"的说法）；
   - 框上方指针标签 `head / p / prev / q`，多个指针落在同一结点时横向错开（模板处理多指针的做法）。
   末端画 `∅` 端标和一根箭头，强调"最后一个结点的 next 是 NULL"这个最常错的知识点。
   额外提供**内存地址层**（可开关）：框下方显示 `0x1a2b`，讲"指针存的是地址"时打开。
3. **图例条**：6 个语义色，与 §3.2 一一对应。
4. **复杂度条**：当前操作的 `O(?)` + 是否需遍历 + 是否需前驱，用 chip 展示。
5. **当前操作解说**：一句话，随步骤实时更新，措辞写"人话"而不是伪代码
   （写「p 向后移动一个结点」，不写「p = p->next」）。
6. **播放控制**：六键 + 对数速度滑杆（1–400 步/秒），与模板一致。
7. **统计 chip ×4**：结点数 / 已访问 / 指针移动次数 / 进度 `4 / 17`。

**右栏（side）3 张卡**：

| 卡片            | 内容                                                                                              | 交互                                                           |
| :-------------- | :------------------------------------------------------------------------------------------------ | :------------------------------------------------------------- |
| 操作与数据      | 初始序列输入框（支持逗号/空格/换行/中文逗号）、应用 / 随机 / 清空、值输入、位序输入、6 个操作按钮 | 非法输入就地红字提示（模板 `.hint.error`）；操作执行中按钮禁用 |
| C 代码 / 伪代码 | 与当前操作对应的 C 代码，行号 + 当前行高亮 + 结构性行灰显；可切「伪代码 / 完整 C 函数」           | 随播放自动滚动到高亮行（`scrollIntoView` 平滑）                |
| 要点提示        | 随步骤变化的 1–2 条易错点                                                                         | 危险操作（删头结点、删尾结点）额外用 `--warn` 左边框           |

**交互细节**（这些是"像模板"的关键，容易被忽略）：

- 空格播放/暂停、`←/→` 单步、`Home/End` 首尾、`R` 重置、`N` 随机 —— 与模板完全一致的键位；
- 播放到末尾按钮变「⏸」→「▶ 重播」；播放中速度滑杆可实时改；
- 结点被删除时不瞬间消失：先变红（150ms），再下移 + 淡出（260ms），箭头同时改指；
- 可视化（链表 / 栈 / 队列）的逐步轨迹依赖后端 `algo/*_trace.py`，**不做前端降级**：后端离线时顶栏显示「离线模式」、挂启动横幅并禁用「执行 / 重置」，避免复制第二份算法导致前后端漂移；（刷题 / 答疑 / 首页指标则自动降级到本地快照，详见 README「架构与设计取舍」。）

## 六、数据契约：后端返回轨迹

这是本方案唯一需要改后端接口形态的地方。以「头插」为例：

```jsonc
// POST /api/linkedlist/insert-head   {"value": 7}
{
  "code": 0,
  "msg": "ok",
  "data": {
    "op": "insert-head",
    "length": 6,
    "trace": [
      {
        "seq": 0,
        "nodes": [                      // 本步结束时的链表现状
          {"id": "n1", "value": 3, "label": "a1"},
          {"id": "n2", "value": 1, "label": "a2"}
        ],
        "head": "n1",                    // 头结点 id，渲染 head 指针
        "ptr": {"p": null, "prev": null, "q": null},   // 各指针停在哪个结点
        "mark": {                        // 高亮语义
          "compare": [], "visited": [], "new": ["n9"], "remove": []
        },
        "line": 2,                       // 高亮第几行代码
        "counters": {"visited": 0, "moves": 0, "compares": 0},
        "info": "申请新结点 s，写入数据 7"
      }
      // … 后续步骤
    ]
  }
}
```

要点：

- `nodes` 是**快照**而非增量，前端不需要自己维护状态，回退零成本；
- `ptr` 只给 id，位置由渲染层算，前后端不耦合坐标；
- `line` 对应 `algo/linkedlist.py` 里登记的代码行号，切「伪代码 / 完整 C」时用两套行号映射；
- `info` 直接是给人看的中文，前端不拼文案（避免"后端说一套、页面写一套"）。

兼容处理：保留现有 `GET /api/linkedlist`、`/insert-tail` 等**只返回最终状态**的接口，
用于快速自检和 curl 调试；`trace` 版本挂在同路径上（带 `?trace=1` 或新路径 `/api/linkedlist/trace/*`），
具体形式实现时再定，不影响页面。

## 九、需要你确认的三件事

1. **渲染方式**：按方案用 SVG（推荐，文字清晰、箭头自动跟随、CSS 过渡即可），

   如果你希望后端保持"只返回最终状态"，前端也能自己造帧，但会出现两套算法。
3. **现有 `visual.html` 里的栈 / 队列 / 二叉树 / 排序四模块**怎么处理？
   - A. 只留单链表，其余归档到 `web/legacy/`（最贴合你列出的 4 项功能）

   - C. 五个都保留在同一页做 tabs（当前形态，但和"单链表做深"有冲突）

我的建议是 **1 用 SVG + 2 改轨迹 + 3 选 B**。你确认或调整后，我从 P0 开始写。
